# Data Quality Report

Generated by `scripts/build_dataset.py`. The raw data is synthetic and ~0.5% of rows were deliberately corrupted to mimic real pipeline defects; this report shows what the cleaning step found and how each issue was handled.

**Rows:** 20,457 raw transactions -> 20,407 clean (50 removed). 3,000 customers.

## Issues found and fixed

| Check | Rows affected | Action |
|---|---:|---|
| Inconsistent transaction_type casing/whitespace | 20 | Standardised to canonical labels |
| Duplicate transaction_id | 20 | Dropped (kept first occurrence) |
| Unparseable transaction date | 4 | Dropped |
| Date outside the dataset window (future / pre-launch) | 4 | Dropped |
| Non-positive amount | 12 | Dropped (cannot be inferred) |
| Orphan customer_id (no matching customer) | 10 | Dropped |
| Failed transaction with no failure_reason | 15 | Labelled 'Unspecified' (kept: the failure is real) |
| Successful transaction carrying a failure_reason | 8 | Reason cleared (status is the source of truth) |
| Missing age_band (customers) | 90 | Labelled 'Unknown' (valid missingness, kept) |

## Validation checks on the cleaned data (all pass)

- transaction_id is unique
- customer_id is unique
- All transactions reference an existing customer
- All transactions reference an existing product
- All transactions reference an existing channel
- All customers reference an existing region
- All amounts are positive
- All dates fall inside the dataset window
- No transaction occurs before the customer's signup date
- status contains only success / failed
- Every failed transaction has a reason; no successful one does
- Failed transactions earn zero fee, successful ones earn a fee
- No missing values outside failure_reason

## Clean dataset summary

- Period: 2024-10-01 to 2026-09-30
- Success rate: 95.97%
- Revenue (sum of fees on successful transactions): INR 860,832
- Transaction value (successful): INR 79,333,764
