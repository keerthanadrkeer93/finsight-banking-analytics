# FinSight: Banking & Customer Analytics

A lightweight analytics dashboard for a fictional FinTech/banking business. It turns raw transaction, customer and product data into answers a business team can act on: how revenue is changing, what is driving the change, and where transactions are failing.

It is a static single-page app. There is no backend, database or paid service: the cleaned CSV files are loaded in the browser and every metric is calculated client-side.

> **Status:** the Executive Overview is complete, built and verified locally. Customer, Transaction and Insights pages are planned and not built yet.

## Business problem

Leadership of a (fictional) digital bank needs to know, at a glance:

- Is revenue growing, and **why**?
- Which products, regions and customer segments drive it?
- Are transactions failing, where, and for what reason?
- What changed compared with the previous period, and what should we investigate?

## What the Executive Overview does

- **Six KPIs** with sparklines: revenue, transaction volume, active customers, average transaction value, success rate and revenue growth.
- **Six charts**, each titled with the question it answers: revenue trend, volume trend, revenue by product, revenue by region, success vs failed (with top failure reasons), and customer segment contribution.
- **Working filters** for date range (30D, 90D, 12M, All, Custom), region, product, customer segment and channel. Every KPI, chart and sentence recomputes from the filtered data.
- **Cross-filtering:** click a product, region or segment to filter the whole page to it.
- **Period comparison:** compares the selected period with the immediately preceding window of equal length. Each KPI shows Improved, Declined or Stable, and the trend charts overlay the previous period.
- **Key Takeaway:** a plain-language summary of the most important change, its main driver and a watch-out, generated from the data (nothing is hard-coded).
- Mobile-friendly layout (responsive header, compact filters and bottom-sheet filters) with loading, error and empty states.

## Dataset

All data is **synthetic**, generated by `scripts/build_dataset.py` (fixed seed, so the output is identical on every run).

| File | Rows | Contents |
|---|---:|---|
| `data/transactions.csv` | 20,407 | One row per transaction attempt: customer, product, channel, date, type, amount, fee, status, failure reason |
| `data/customers.csv` | 3,000 | Region, value segment (Premium, High Value, Standard), signup date, age band |
| `data/products.csv` | 6 | Instant Credit, Platinum Card, Everyday Debit, Savings Plus, Legacy Wallet, Forex & Remittance |
| `data/regions.csv` | 5 | North, South, East, West, Central |
| `data/channels.csv` | 5 | Mobile App, Web Banking, POS, ATM, Auto-Debit |

Period covered: 1 Oct 2024 to 30 Sep 2026 (2 years). The schema is documented in [`data/DATA_DICTIONARY.md`](data/DATA_DICTIONARY.md).

The generator plants realistic business patterns so there is something genuine to analyse: festive-season and fiscal-year-end seasonality, revenue concentrated in Premium customers, a fast-growing product, a flat high-revenue product and a declining legacy product, one deteriorating region, and a rise in mobile authentication failures.

### Cleaning pipeline

The script first corrupts about 0.5% of rows on purpose (duplicates, invalid dates, negative amounts, orphan customer IDs, inconsistent labels, missing or contradictory failure reasons), then cleans and validates the result, so the cleaning step has real work to do:

- 20,457 raw transactions became 20,407 clean ones. 50 invalid rows were dropped and 43 values were repaired.
- 13 validation checks run on the cleaned data (unique keys, referential integrity, positive amounts, dates inside the window, no activity before signup, status and failure-reason consistency). The build fails if any check fails.
- The full report is in [`docs/data_quality_report.md`](docs/data_quality_report.md).

## KPI definitions

| KPI | Definition |
|---|---|
| **Revenue** | Sum of `fee` on **successful** transactions. Failed transactions earn nothing. |
| **Transaction volume** | Count of all attempts, successful or failed. |
| **Active customers** | Distinct customers with at least one successful transaction in the period. |
| **Average transaction value** | Mean `amount` of successful transactions. |
| **Success rate** | Successful transactions divided by all attempts. |
| **Revenue growth** | Revenue in the selected period versus the previous period of equal length. |

**Assumptions**

- Presets (30D, 90D, 12M) are anchored to the last date in the data (30 Sep 2026), not today's date, so they never come back empty.
- A KPI counts as **Stable** if it moved less than 1% (or less than 0.5 percentage points for the success rate). Otherwise it is Improved or Declined. For all six KPIs, higher is better.
- Charts show months for periods over about four months, and weeks for shorter ones.
- Comparison is switched off automatically when there is not a full earlier window of data (for example "All time").
- A zero denominator never produces `NaN`: ratios return "n/a" and rates return 0.

## Architecture

```
scripts/build_dataset.py  -->  data/*.csv  -->  React app (browser)
 generate, corrupt, clean,      cleaned,         loads CSVs once, joins them in memory,
 validate (pandas, NumPy)       committed        computes all metrics client-side (TypeScript)
```

- **Stack:** React 19, TypeScript, Vite, Tailwind CSS 4, Recharts, PapaParse. Tests use Vitest. The data pipeline uses Python with pandas and NumPy.
- The CSVs are imported as raw text (`?raw`), parsed once, and joined into a single array. Each filter change runs one pass over about 20,000 rows, which takes a few milliseconds.
- All analytics live in `src/lib` as pure functions, separate from the UI, which is what makes them testable.

```
src/
  lib/         dataset, filters, analytics, kpis, takeaway, formatting (no React)
  components/  layout, filters, KPI strip, takeaway, charts
  pages/       Overview
tests/         regression tests for src/lib
data/          cleaned CSVs + data dictionary
scripts/       dataset generator / cleaner / validator
docs/          data-quality report, screenshots
```

## Getting started

Requirements: Node.js 20.19+ (or 22+) and, only to regenerate the data, Python 3.10+.

```bash
npm install
npm run dev          # http://localhost:5173
```

Other commands:

```bash
npm run build        # type-check + production build into dist/
npm run preview      # serve the production build locally
npm run typecheck    # TypeScript only
npm test             # run the regression tests once
npm run test:watch   # re-run tests on change
```

Regenerate the dataset (optional, the CSVs are already committed):

```bash
pip install -r scripts/requirements.txt
python3 scripts/build_dataset.py     # use `python` on Windows
```

## Testing

`tests/overview.test.ts` covers the Executive Overview analytics. Expected values were computed independently with pandas, not with the code under test.

Manual browser review has not been committed in this repo yet. The local verification step is to run the app and inspect the responsive layout at a small viewport before adding screenshots to the portfolio narrative.

- All-time baselines: revenue, transaction count, success rate, successful transaction value.
- The 12-month period and its previous-period comparison, plus a quarter-over-quarter case.
- Region, channel, segment and product filters, multi-select, and combined filters.
- Date handling: presets, reversed and out-of-range custom ranges, single days.
- Rules on a small hand-built dataset: failed transactions earn no revenue, orphan customers are dropped, active customers need a successful transaction.
- Empty selections, empty datasets and zero denominators: no `NaN` ever reaches the UI.
- Key Takeaway output computed from the data.

## Deployment

The build output (`dist/`) is plain static files, so it can be hosted free on Vercel, Netlify, Cloudflare Pages or GitHub Pages. On Vercel, import the repository and use the defaults (build command `npm run build`, output directory `dist`).

## Key findings (last 12 months vs the 12 before)

- Revenue rose **18.9%** to about ₹4.68 lakh, while the success rate **slipped from 96.2% to 95.8%**: growth and reliability are moving in opposite directions.
- **Instant Credit** (+69%) drives the growth. Platinum Card is a large but flat product (24% of revenue, +0.5%). Legacy Wallet is shrinking (−46%).
- Premium customers are about 12% of active customers but generate 37% of revenue.
- **East** is the only declining region (−13%), while West grew 35%.
- Mobile App has the most volume (39%) and the highest failure rate: 5.7% over the year, up from 4.0%, and 9.9% over the last 90 days, where authentication failures are 69% of its failures.

## Known limitations

- **Period comparison is not seasonally adjusted.** It compares with the immediately preceding window, so comparing January to March with the festive quarter before it will show a decline that is partly seasonal.
- The data is synthetic. The patterns are deliberate and the conclusions illustrate method, not real banking behaviour.
- Only the Executive Overview is built so far. Customer, Transaction and Insights pages are planned.
- Region belongs to the customer, not the transaction, so "region" always means the customer's home region.
- 421 of the 3,000 customers have no transactions, so they never appear as active.
- Rate changes are not tested for statistical significance. The takeaway only guards against tiny samples (fewer than 30 transactions overall, or 150 per channel).
